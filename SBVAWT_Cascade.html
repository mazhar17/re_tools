2 · One-at-a-time sensitivity analysis

Perturb selected inputs by ±p% around the current first operating case. The reported sensitivity is the central dimensionless elasticity, S ≈ (ΔY/Y)/(ΔX/X). It is local, not a global Sobol/Morris index.

3 · Model-form switch study (dynamic stall / flow curvature)

Runs all four dynamic-stall / flow-curvature corners and reports the spread in peak net CP and in the tip-speed ratio at peak. Four solver runs.

4 · Model-form study: induced angle and dynamic stall

Varies the two settings the legacy solver fixed, and reports the spread in peak net CP and in the tip-speed ratio at peak. Up to thirteen solver runs, so budget a few minutes. The azimuthal-resolution group is not a model choice; it is the numerical noise floor the other spreads should be read against.

The induced-angle option acts on the tabulated and custom-polar (XFOIL, code 9000) paths. For the analytic airfoil codes it has no effect, because those routines already use the dimensionally consistent form; the study reports which case applies.

1 · Two-parameter design map

Sweep two design/operating variables and map a scalar performance metric. Each cell is an independent full TSR sweep. Start with 4–5 points per axis; large grids can be slow in the browser.

AEP / Energy Yield

Convert aerodynamic performance into a preliminary annual-energy estimate using a Weibull wind-speed distribution.

5 · Annual Energy Production from Weibull wind distribution

Calculate AEP from Weibull shape k and scale c [m/s]. The rotor geometry is held fixed while Reynolds number scales with wind speed. By default, each wind-speed bin runs a complete TSR sweep and uses maximum net CP (ideal variable-speed / MPPT operation).

0 = no rated-power cap.
Weibull CDF: F(V)=1−exp[−(V/c)^k]. Bin probability is evaluated exactly from the CDF; AEP is Σ P(Vᵢ) × 8760 × probabilityᵢ. Net CP is used, including modeled strut loss.

6 · Weibull k–c scenario matrix: CP-optimal versus AEP-optimal

Builds one physics power curve P(V) per design, then integrates it against every k–c cell. Because P(V) does not depend on the wind-resource fit, the whole scenario matrix costs no extra solver time.

Benchmark interpretation notes

  • Battisti operating mode: approximately 400 rpm while free-stream speed varied; use constant turbine-speed mode.
  • Solidity convention: this workbench uses σ = Nc/R = 2Nc/D. Battisti's reported 0.25 therefore becomes approximately 0.4961 in this app.
  • Reynolds coverage: the Battisti cases span blade Reynolds extrema of roughly 29,000–200,000; generate Reynolds-dependent NACA 0021 polars across that envelope.
  • Blockage: the reported H-rotor open-jet correction was about 1.5% and was not applied to the embedded points; the app likewise leaves the measured values unchanged.
  • Lee 2025: embedded values are source-stated peak values only; no graph-digitized full curves are introduced.

AI / Deep Learning

Train and test a browser-side neural-network surrogate on physics-solver data, with explicit envelope and Physics-vs-DL checks.

Physics-guided surrogate workflow: the neural network is trained only on outputs generated by the aerodynamic solver. It is an approximation for rapid exploration, not a replacement for XFOIL, the VAWT physics model, or experimental validation. Predictions outside the sampled design envelope are flagged as extrapolation.

1 · Generate a physics-labelled training dataset

Latin-hypercube sampling generates independent turbine designs. Each design runs one complete TSR sweep, so every valid TSR station becomes a labelled example. This produces many training rows from relatively few expensive physics runs.

40 designs usually produce roughly 1,000–1,600 TSR-labelled rows.
Uses the current Input-tab minimum and maximum TSR.

Inputs: TSR, solidity, Re, aspect ratio, pitch and H/D. Outputs: net CP, gross CP, CQ and CD. Inputs are min–max scaled and outputs standardized from the training subset only.

4 · AI-assisted design screening and physics verification

The surrogate ranks a large candidate set; the solver then re-checks the leaders. Per-candidate wall-clock time is recorded on both paths, so the speed-up is measured rather than asserted.

Latin-hypercube sample drawn inside the surrogate's own envelope.
Matches the solver sweep so the timing comparison is like for like.
Ranking by annual energy scales the reference Reynolds number with wind speed, exactly as the physics power curve does. Bins whose scaled Reynolds number leaves the sampled surrogate envelope are counted and reported; they are extrapolation, not prediction.
Each is a full solver run. Budget roughly 2–5 s per design in the browser.

5 · Adaptive resampling

Use this when the held-out R² falls short of the acceptance criterion. Extra physics designs are generated around the worst unseen-test points, appended to the dataset, and the surrogate is retrained in step 2.

Interpretation

  • Training/validation/test separation: reported test metrics are calculated on rows excluded from gradient updates and validation monitoring.
  • Surrogate scope: a good test R² does not establish physical validity; it shows how closely the DNN reproduces this solver within the sampled envelope.
  • Extrapolation: neural-network predictions outside the training ranges are flagged and should not be used as engineering conclusions without new physics simulations.
  • Recommended workflow: use the DNN for rapid screening, then verify promising designs with the physics solver and ultimately with experimental/independent data.

What this is

A Python port of a FORTRAN 77 code for straight-bladed Darrieus turbines, running in your browser on Pyodide. It implements multiple-streamtube, double-multiple-streamtube and cascade aerodynamics, with optional Migliore flow curvature and four dynamic-stall models.

How far to trust it

  • Seventeen reference cases match a double-precision rebuild of the original Fortran to ~5×10-6, which is the print rounding of the original's own output.
  • Only the cascade model (THEORY = 3) has been code-verified against the original implementation. The two streamtube paths and the design mode are ported but never cross-checked against the original. Treat their output as unverified.
  • The original is single precision and the solution becomes highly numerically sensitive beyond the CP peak. Rebuilding it in double precision moves results by up to 10-3, and much more in the collapsed post-peak regime.
  • A handful of cases still differ: see the README shipped with the package for the open list.

Quirks deliberately preserved

These look like mistakes in the original but change the numbers, so the port reproduces them rather than silently improving on them.

  • SUPPORT and BLADE are uninitialised in performance mode — zero, not one. This switches the finite-aspect-ratio correction back on; defaulting them to 1 inflates CP by about 5%.
  • CNCTXFOIL is called before every airfoil-specific routine and mutates its arguments, so the override receives an already-clamped Reynolds number.
  • ASTAL is rewritten by the aspect-ratio iteration inside each coefficient routine, so the stall model must read it live rather than caching it on entry.
  • The drag block of stall.FOR passes ALM instead of ALM2 for airfoils 18 and 180.
  • cnctXFOIL adds an induced-angle correction in radians to an angle held in degrees.
  • cnct21 interpolates without dividing by the angle spacing, and hard-codes 31 table rows.

Verification, validation and model fidelity

  • Verification: asks whether this port reproduces the intended equations/source code. The reference-case agreement addresses this question for the cascade path.
  • Validation: asks whether the model reproduces physical turbine behaviour. Use the Results tab's optional reference-data comparison for that purpose.
  • Legacy fidelity: this build deliberately preserves documented FORTRAN quirks so verified cases remain reproducible. A separate corrected-physics mode is not enabled here because it would require its own verification and validation campaign.
  • Connectivity: the aerodynamic package is embedded in this HTML, but the Pyodide runtime is loaded from a CDN; therefore this file is not fully offline.

Custom XFOIL airfoil path (AIRFOIL = 9000)

  • This is an additive analysis path; the verified legacy airfoil routines are not altered.
  • Seven Reynolds levels are generated from geometry with browser-side XFOIL and interpolated continuously in both signed angle of attack and Reynolds number.
  • Viterna–Corrigan and a Montgomerie smooth-blend implementation extend the static XFOIL data to ±180°. Extrapolation choice is a model-form uncertainty and should be checked against measured data where possible.
  • XFOIL non-convergence is surfaced in the Airfoil Generator quality-control table rather than silently treated as valid data.
